# 实施规则

上位项目约束见 [AGENTS](../AGENTS.md)。本文件只列实现细则，不重复变更日志。

## 状态和通信

- 老人状态唯一入口 SetElderState；导航通过组件/AIController，UI 通过 ProjectUserWidgetBase/玩家 Controller。不得让摄像机或 UI 直接覆写 CurrentState。
- 控制对象用明确引用；处理对象销毁、离场、重选、解绑和重入。AddUniqueDynamic 不是全部生命周期测试的替代品。
- 派生显示/缓存可以存在，但注明来源和过期策略。监控日志记录过去，不能作为当前老人状态权威。
- 内部紧密组件可用具体类型引用；跨系统选择合适接口/事件，不强制全接口化。当前监控具体类型耦合是已记录边界，不伪称完全解耦。
- 不使用状态轮询 Tick、每帧 GetAllActorsOfClass 或 Delay 串接业务状态；动画计算、输入更新和受控转身 Tick 保留其正常用途。

## 资产与运行

- 原 Blueprint 是表现与配置入口，C++ 是可维护行为基础；本轮文档任务不授权再迁移父类。
- 修改根运动、动画图或输入须保留轻按、持键、连续方向、松键、禁移状态及退出接管的既有契约。
- 替换 Mesh/动画先核对 Skeleton、AnimClass、根骨与材料；没有动画不得拿无关动作冒充。
- AI Sight 与显示范围分别验证；摄像机球体只是现状，未来 FOV/LOS 应复用同一摄像机并单独验收遮挡/边缘行为。
- 对实例可编辑的样条，Construction 不得覆盖用户控制点。角色运行配置与正在执行的请求要通过明确启动/切换入口同步。
- 天气灯光读取完整组合，不猜按钮来源；保持 Timeline 中途反向和重复目标不重播。
- 多老人/摄像机/房间不使用全局单例姓名状态；后续历史需要稳定 ID/结构化记录时单独设计兼容迁移。

## 文档维护

修改系统职责、变量所有权、Enum、接口/事件、公共函数、依赖或核心数据流：更新对应系统页和表格；重要理由写 ADR。只影响局部表现无需重写全部文档。

Content 指南只记录目标/结果、重大变化、关键证据、未解决项。旧日志是历史，不覆盖当前系统页；发现旧完成声明过宽时加明确纠正，不能掩盖此前验证缺口。
